# HANABI ONLINE — ゲーム仕様書 v1.0

作成日：2026-10-27（日本時間）  状態：第一実装・ルール単体テスト済

## 1. 目的・範囲

ブラウザから 2〜5人が同一ルームに参加し、各自が自分の手札のみ見えない協力型カードゲームをプレイする。アカウント登録不要、共有URLとプレイヤー名だけで参加可能。スマートフォンとPCに対応する。サーバーが全てのゲーム判定を行う。

**含む：** ルーム作成・招待・参加、ホスト権限、再接続、手札の部分秘匿、プレイ・捨て札・色/数字ヒント、5色花火、ヒント/ミス/山札、終了判定、行動/ヒント履歴、全体チャット、虹色の拡張ルール、再戦。

**含まない：** 公式ロゴ・画像、AIプレイヤー、プレイヤー認証、永久保存、観戦モード、永続データベース、音声チャット、ルームパスワード。

## 2. ゲーム画面・遷移

```text
ホーム（ルーム作成/参加）
     ↓
待機室（メンバー・モード・ルームURL・チャット）
     ↓  2〜5人全員オンライン、ホストが開始
ゲーム中（得点・花火・他人の表向き手札・自分の裏向き手札・手番・ログ/チャット）
     ↓  3回ミス / 完成 / 最終ラウンド終端
終了（得点・終了理由・表向きにした全手札）
     ↓  ホストが待機室へ戻る
待機室（同じメンバーで再戦）
```

接続が切れた人の席は維持。ゲーム途中で新規参加はできず、全員が戻るまでその人の手番ではゲームを進められない。待機室ではホストがオフラインのメンバーを外せる。

## 3. デッキ・開始時状態

| パラメータ | 値 |
| --- | --- |
| 基本色 | 赤・黄・緑・青・白 |
| 各色の枚数 | 1×3、2×2、3×2、4×2、5×1 |
| 2/3人手札 | 5枚 |
| 4/5人手札 | 4枚 |
| 初期ヒント | 8/8 |
| 初期失敗 | 0/3 |
| 開始手番 | ランダムな参加者 |
| ゲームモード | `classic` / `rainbow5` / `rainbow10` / `rainbowWild` |

シャッフルはサーバー側で Node の `crypto.randomInt` を使う Fisher-Yates 法。カードごとにランダムIDとヒント情報を保持する。初期配布・カード補充は山札から行い、手札は左から右の順で表示する（新しい札は末尾に入る）。

## 4. 行動とルール

### 4.1 カードを出す `play(index)`

自分の手番で自分の手札から位置（0起点）を選ぶ。選んだ札の数字が同色の完成数+1なら成功し、その花火を1つ進める。成功した5はヒント+1（最大8）。それ以外は失敗（捨て札に追加・失敗+1）。行動後に山札が残っている場合は1枚補充する。

### 4.2 捨て札にする `discard(index)`

ヒントが8個の時は禁止。合法なら手札1枚を捨て、ヒント+1（最大8）。山札があれば1枚補充する。

### 4.3 ヒントを出す `clue(targetId,clueType,value)`

手番、ヒント残数≥1、自分以外の既存プレイヤー、色または数字、合致札が1枚以上という条件を確認する。対象プレイヤーの現在の手札すべてに対して一致と不一致を記録する。一致した位置（1起点）を行動ログに残し、ヒントを1消費する。対象が補充した新カードへ過去のヒントは引き継がれない。

### 4.4 山札と終了処理

カードを出すか捨てた結果、山札の最後の札を引いた場合、**次のプレイヤーから計人数分**の追加手番を許可する。これにより最後の札を引いた人ももう1手番を得る（引いたそのターンとは別）。追加手番が0で終了。先に3回失敗またはすべての花火を完成した場合は即時終了。3回失敗は得点0、その他は積み上がったカードの合計点。

### 4.5 虹色の拡張

- `rainbow5`：虹色スートに1,2,3,4,5を1枚ずつ、色ヒントは「虹」でのみ一致（数字は当然該当数字で一致）。
- `rainbow10`：虹色スートに通常の色と同じ10枚を追加、ヒントは「虹」でのみ一致。
- `rainbowWild`：虹色スートに1,2,3,4,5を1枚ずつ。色ヒントは赤黄緑青白の**全て**に一致し、虹というヒントは不可。プレイ時は虹色スートにのみ属する。

## 5. クライアント表示と情報の秘匿

`playerView(room, viewerId)` が通信に出してよいデータをホワイトリストで生成する。プレイ中は自身のカード `{id, knowledge}` のみ表示し、`suit`/`rank` を決して入れない。他の人のカードは `{id,suit,rank,knowledge}` を送る。山札は残数のみ送る。終了後は全員の残り手札を公開する。

知識情報：`yesColors[]`, `noColors[]`, `yesRanks[]`, `noRanks[]`。メイン画面で肯定ヒントを表示し、カード選択時に否定ヒントも表示する。ヒントが与えられた時点のカード単位の記録とし、カードの位置が左に詰められても正しく残る。

手札に関わる操作はカードそのものをクライアントから受け取らず、インデックスをサーバーがカードへ解決する。ターンのバリデーションはすべてサーバー側で行う。

## 6. ネットワークイベントと認証

通信：Socket.IO（同一Nodeサーバー、同一オリジン）。

| 方向 | イベント | 内容 |
| --- | --- | --- |
| client→server | `createRoom` | `{name}` |
| client→server | `joinRoom` | `{code,name}` |
| client→server | `resume` | `{roomCode,playerId,secret}` |
| client→server | `setMode` | `{mode}`（ホストのみ） |
| client→server | `startGame` | なし（ホストのみ） |
| client→server | `backToLobby` | なし（終了後、ホストのみ） |
| client→server | `playerAction` | `{kind:'play'|'discard',index}` または `{kind:'clue',targetId,clueType,value}` |
| client→server | `chat` | `{message}` |
| client→server | `removePlayer` | `{playerId}`（未接続のみ、ホスト） |
| server→client | `session` | `{roomCode,playerId,secret}`（**本人だけ**） |
| server→client | `roomState` | `playerView` が返す本人用スナップショット |
| server→client | `errorMessage` | エラー文字列 |

認証：プレイヤーIDと24バイト乱数の秘密トークンを組み合わせ、ブラウザに保存する。再接続時にID・トークンを照合し同じ席へ復帰。古いSocketを無効化。ユーザーの参加に氏名・メール等は不要。サーバー再起動後にルームが復元できない点はUIに通知する。

## 7. ログ・チャット

履歴にはイベント種類、プレイヤー名、対象者（ヒント時）、ヒントの内容とマッチ位置、公開されたプレイ/捨て札、成否、発生時刻を保存。**未公開の手札情報はログに記録しない。** 履歴表示は直近150件、サーバー保持300件。

チャットは同室参加者全員に配信。1件300文字まで、同一Socketから750ms未満の連投を制限。表示ではHTML特殊文字をエスケープし、タグを実行しない。サーバー保持150件、表示100件。ローカルルームにはプレイヤー名・チャット内容が残るので、個人情報の投稿は避ける。

## 8. エラーハンドリング / 非機能要件

- 無効な操作は状態を変更せず、本人へ日本語エラー通知。
- 入力上限：名前20文字、チャット300文字、Socket受信ペイロード最大12KB。
- ブラウザ再接続時の復旧対象は**同じサーバープロセス内**のルームのみ。
- ブラウザの横幅に合わせて花火・札・他者手札・チャットのレイアウトを変更。
- HTTPの静的パスは `index.html`, `app.js`, `style.css` のみ。`/health` は監視用。
- 一定期間接続者のいない放置ルームはメモリから削除される。
- ログイン/DB/暗号化通信の設定は配備先HTTPS+WSSによる（Nodeのローカル起動はHTTP）。

## 9. 受け入れテスト観点

1. 2〜5人でルームに参加、6人目は拒否。
2. 2/3人は5枚、4/5人は4枚。
3. 他者の手札の色/数字が見えるが、自分のカードはサーバー応答にも含まれない。
4. 色ヒントは対象の一致する全カードに肯定、その他には否定情報を付ける。
5. 8ヒントでは捨て札不可。ヒント0ではヒント不可。
6. 5を完成させるとヒントが1回復する（最大8）。
7. 3回失敗は即終了・得点0。全色完成は満点即終了。
8. 最後の札を引いてからプレイヤー人数分のターンで終了。
9. 一時切断後に復帰すると、元の手札・手番・履歴を継続。
10. 別の端末の正規の復帰トークンがなければ、元の席を盗めない。
11. チャット・行動/ヒント履歴が全員に反映される。
12. ホストだけがルール変更・開始・再戦を行える。
13. 3種類の虹色拡張の枚数・ヒント処理・最高点が正しい。
14. Android/iPhone/PC の2画面以上で操作・同期を確認する。

## 10. 既知の制約・次回改善案

- **実地の複数ブラウザ接続テストは環境上未実施**。Node標準のルールテストは通過済み。ネットワーク環境に置いてE2E確認すること。
- ゲーム途中のホスト移譲・途中参加・席順変更は未対応。
- ルーム状態はメモリ上のみで、サーバー停止・Render無料プランのスリープで失われる。
- 身内向けMVPのため、荒らし対策・公開チャットモデレーション・永続セッション管理・レート制限の強化は必要に応じて追加。
- 将来機能候補：観戦、保存済みリプレイ、短時間の切断でのホスト移譲、独自デザインのアニメーション、音楽、ホストによる再配置。
